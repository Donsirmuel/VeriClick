I'm the owner of getvericlick.site. I want to explain what happened and what I've done to fix it.

VeriClick is a link protection service — it creates tracked links that verify visitors and block bots. When users sign up, they can create links. Previously, if a user didn't have their own domain set up yet, the link would temporarily use getvericlick.site as the host. That's how the phishing link ended up on my domain.

The link /r/44wkekw/ was created by a new user who signed up and immediately created a phishing link. I've permanently disabled that link (it returns a 410 Gone now) and deactivated the user's entire account.

But I didn't just remove the link — I changed the system so this can't happen again. I removed the /r/* path from getvericlick.site entirely at the server level. The domain no longer serves any tracked links at all. It only hosts the dashboard and admin panel now. Every user must use their own domain for tracked links — I can't create links on getvericlick.site even if I wanted to.

I've also added several safety measures: destination URL blocklists, Google Safe Browsing checks on every new link, rate limiting, abuse reporting, daily scanning of all active links, and an expanded terms of service with clear abuse policies.

All existing links that were using getvericlick.site have been disabled and their owners notified.
